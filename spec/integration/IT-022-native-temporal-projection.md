# IT-022: Project admitted native temporal inputs through genuine TL owners

## Objective

Construct the FR-350 projection inputs without running either evaluator. A
successful `project_tl` returns a constructor-private value retaining genuine
TL formula, proposition-map, trace or position-history, and request reader
outputs. It retains the original native facts and independent observation-owner
views. A failed premise returns a typed non-value and no partial projection.
The same IR-1005 integration leg also owns strict correspondence reading and
result joining. Their implementation and tests remain required before this leg
can claim FR-350 completion; a projection-only result is not completion.

## Target Integration

Original QSL source and model evidence → QSL emitter → strict IR reader →
checked subject, owner-bound classification and admitted native valuation rows →
IT-020 formula constructor → actual TL proposition, trace/history and request
constructors and strict readers. The native subject name comes from the selected
authored occurrence. The request's correspondence name is the public bridge
profile `quire.native-temporal-correspondence/v1`, not a computed identity.

## Preconditions

The classification retains the actual owner-issued checked-package admission
binding. Before using its facts, `validate_mapping_binding` requires the supplied
package to retain that binding, requires the subject's package membership, and
compares the complete value with owner reclassification under the same surrounding
closure. Independent equal-content admissions do not exchange classifications;
clones retaining the original owner admission can supply a newly read subject.

The bridge consumes QSL `ValuationEvidence` and its ordered rows as admitted input
facts, not as an attestation of a separate observation producer or package
admission. It checks each row against the selected occurrence, trace position,
anchor, immutable capture instance and selected observation revision. Agreeing
duplicate rows remain distinct owner rows and are rejected as duplicate projection
cells; the bridge never calls `value_of` to erase them. A Boolean false is present
data. No absent, conflicting or evicted fact becomes false.

## Inputs

`project_tl` takes the actual checked package and subject, QSL classification,
surrounding closure, the actual native checked-package `EvidenceRequest`,
ordered `ValuationEvidence`, exact occurrence and `ValuationInstance`, actual admitted observation revision, and independent TL/QObs owner
selections and limits. This native input spelling is the pending IR-1378 owner
correction to FR-350's legacy `Trace` spelling; no adapter guesses an opaque
observation identity from a numeric position. IR-1377 owns normalization of the
TL request dependency cohort. Selection structs group references to real owner values;
they do not replace their records, assert trust, or supply an evaluator callback.

## Test Procedure

1. IT-022-SC-01: Emit original source once and admit the bytes twice. Require a
   local subject and local classification to pass; substitute only the foreign
   classification while keeping the local subject and require a named admission
   refusal before formula construction. A newly read subject on a package clone
   retaining the same admission is accepted, including after moving the package.
   Preserve the existing foreign-subject and altered support/definition/closure
   controls.
2. IT-022-SC-02: Admit native rows through `ValuationEvidence::admit`. Construct
   every required position/proposition value from these rows, checking the exact
   occurrence, anchor, capture instance, revision and checked operand. Compare
   true and explicit false cells in actual admitted TL owner values. Remove a
   cell for incompleteness; duplicate an agreeing row, swap its operand or
   position, or foreign-bind the occurrence/revision for refusal. Repeated formula
   uses retain the source relation and do not excuse duplicate input cells.
3. IT-022-SC-03: Construct closed and prefix future requests, and individually
   supported bounded-past requests with complete origin history. Preserve the
   surrounding target independently of decision closure. A history cutoff is
   incomplete, not a new origin. Unsupported classifications retain every
   original dimension and yield no projection. A named native occurrence selects
   the exact authored subject name even when declarations share a checked node.
4. IT-022-SC-04: Retain fixed-sample epoch, period and unit as actual owner data.
   Refuse a changed clock or event-count reinterpretation. Missing samples are
   incomplete. If an owner cannot represent an otherwise authored supported
   selection, preserve its typed refusal and record the exact upstream limitation;
   do not narrow FR-350, invent a conversion or copy an owner record.
5. IT-022-SC-05: Supply independent admitted clock, decision and surrounding
   progress/closure, completeness and availability views. Check native bindings
   against those values and pass the genuine views to the request owner. Derive
   and strict-read the request, retaining the exact admitted output with its
   source formula/map/trace/history. No evaluator or result reader is invoked.
6. IT-022-SC-06: Precharge bridge node, position and cell visits and reject before
   processing a first excess unit. Bound each generated record with its caller
   byte ceiling using the owner producer's bounded writer. Check actual operations
   exactly at their measured bound and one less, with all other settings above
   their measured counts; verify fresh counters and no returned partial value.
   QSL view/classifier work remains excluded under the owner default. Owner
   readers keep their independently supplied finite limits. Support and cause
   counters belong to the later join and are not qualified by projection tests.

## Expected Results

Reachable projection cases return actual immutable owner-admitted artifacts and
preserve their native correspondence inputs. Every failed premise is a typed
unsupported, incomplete or refused result without a successful partial value.
The integration preserves current owner limitations as limitations, not successful
FR-350 evidence. Full correspondence reading, result joining, supersession and
complete seven-counter qualification remain open under IR-1005.


## Correspondence and strict reading

The constructor-private projection retains its original package admission and
canonical bridge correspondence bytes. The correspondence preserves the actual
source occurrence span, declaration, selected owner lock/profile, original
predicate terms with their TL proposition relation, ordered intervals, native
anchor and capture values, exact clock parameters, observation bundle and each
independent QObs owner record. It retains complete formula, proposition map,
trace/history and request byte values without copying their owner schemas.
Native valuation row order and all six row bindings remain explicit. Native
completeness facts remain exact opaque source facts; equal progress numbers or
closed states do not attest a mapping to QObs member identities.

`read_tl_projection` reconstructs the expected value through the same genuine
constructors/readers with independent original inputs and fresh caller counters.
It compares complete canonical bytes. Unknown, duplicate, missing, reordered,
trailing or noncanonical members and changed owner values refuse. Neither the
constructor nor reader invokes an evaluator.

## Remaining owner prerequisites

Full FR-350 qualification is pending the IR-1377 dependency cohort and IR-1378
native input correction. The native full-predecessor operations supplied by QSL-1795 are consumed as
original owner APIs. The TL result owner still needs a public, non-evaluating
operation that authenticates its complete actual direct predecessor; identities
alone cannot discharge that requirement. The bridge preserves a typed TL-side
authority refusal until that owner supplies the capability. The supported fixed-sample unit domain remains FR-350's authored
domain; the TL request owner's current nanosecond-only past restriction is an
upstream limitation rather than a narrower integration contract.

## Result joining and strict join reading

`join_tl` consumes original native reports and actual owner-admitted mapped TL
results. It re-reads the native report with the original checked subject,
request and caller-owned `NativeJoinBudget`, and the mapped result through the
non-evaluating mapped-result reader against its retained original source result.
It does not call the TL report reader that executes assessment again. Missing
results and refused owner reads enter the authored decision-table predicates;
they do not become substitute values. Every predicate is evaluated independently,
the first matching row selects the decision, and each matching non-final cause
is retained once in table order. Only equal-final agreement carries a Boolean.

The join retains complete native, mapped and correspondence byte values and any
supplied prior join bytes. Its strict reader reconstructs the expected join from
original owner values and compares the complete canonical record. Support visits,
causes, work and bytes use independent caller counters. Corrected success remains
blocked on the TL owner's full direct-predecessor admission capability;
this does not waive FR-350-AC-5. Rows unreachable through sealed owner producers
must have concrete owner evidence and must not be reported as tested by direct
construction of a fake result.

## Original bridge definition admission

The integration owns `definitions/native-temporal-correspondence-v1.json`, whose
literal authority `agent-ix/quire-integration`, definition identity
`native-temporal-correspondence/v1`, public profile and version are original
published domain values. No identity is computed from bytes or inferred from a
profile name. `read_tl_bridge_definition` strictly checks the closed canonical
record and exact membership in that authored definition. Its constructor-private
result is required by projection selection and retained as complete bytes in
the correspondence. Changed authority, identity, profile and version each have
a named refusal. Unknown, duplicate, missing, trailing and noncanonical members
refuse; the exact record byte bound admits and one byte short refuses.

## Retained activation and exact source occurrence

Before constructing a TL artifact, projection calls the original native
`ActivationInput::contradiction` admission against the exact obligation and
caller ledger. A changed payload under a retained semantic trigger is an owner
contradiction. An unchanged redelivery uses the actual retained payload and
immutable capture environment, without replacing them with current initializer
facts or re-running initializers. Missing retained captures and evictions refuse
or remain incomplete. Exposed ledger instance/result row counts are precharged
before the owner clone/scan; current delivery/origin/capture/eviction visits are
also bounded. Owner clone allocations are transient owner behavior, not a claim
that every internal allocation is a generated bridge record.

Source correspondence selects the actual admitted source-map entry by all three
occurrence members: node, role and ordinal. It does not use a node-only first
source span when multiple authored declarations share one semantic node.

Native assessment execution remains independent of native report outcome and TL
execution. A failed native execution may still produce an evaluated Boolean
report; that value must not override the ordered `result-failed` row. Unequal
execution premises also retain the applicable later mismatch cause.

The currently retained structural model-root values do not expose the authored
model aliases or their alias order. That mandatory FR-350 correspondence axis
remains blocked on actual owner-retained facts or an owner contract correction
(IR-1005 comment `ba739c71`); root-node order is not presented as alias order.

A retained capture's original owner anchor must equal the supplied native
instance anchor; a previously captured value cannot be replayed as a capture at
a different admitted observation. A retained `ActivationFault` preserves the
native owner's complete subject (`Guard`, `Anchor` or named `Capture`) and kind.
`Missing` remains incomplete and `Refused` remains refused; neither is replaced
with a generic missing-capture result. Regressions obtain those retained faults
through genuine native evaluation before calling the non-evaluating bridge.


## Native full-predecessor admission

Projection selection carries the caller's actual finite native
`ReportPredecessorLimits` separately from the seven bridge counters and TL owner
limits. The native domain counts byte inspections/copies and temporary ownership;
these are not silently recast as FR-358 IR work or bridge item visits. Each native
owner operation receives its original finite operation ceilings. The join retains
the actual bounded-writer and successful predecessor-validator usage receipts;
the native strict reader remains independently bounded by its supplied owner
limits and its existing shared IR budget, without claiming an unavailable reader
usage receipt.

The join writes native values only through `Report::to_owner_bytes_bounded`.
For a correction it obtains the actual prior `Report` from the supplied previous
join only when that join's native source was strictly admitted in its exact
context. It supplies that actual full owner value to `CheckedSubject::with_predecessor`
before strict native reading. After that succeeds, it calls the public
`validate_predecessor` operation for its bounded owner usage receipt. Embedded
predecessor bytes are retained by the owner and may be inspected, but the bridge
never reads them a second time to manufacture the expected prior authority.

A genuinely missing or full-value-mismatched direct predecessor selects correction
conflict, retains the original mismatch refusal when present, marks the native
source unadmitted and carries no Boolean. A native owner `PredecessorLimit` remains
its original typed work/storage denial with limit and actual charge; it is an
atomic limit-reached result, not a predecessor mismatch. An unrelated strict
native reader refusal continues to enter the refused decision row. The canonical
join records whether native strict admission succeeded.

A native correction that passes full validation can still stop at the honest
TL-side predecessor authority refusal. That refusal retains the actual successful
native validator receipt; it does not claim complete cross-owner correction
acceptance. Tests use real evaluated and precharged-Meter native reports sharing
one result identity to prove complete-prior substitution fails both validation
and strict reading, together with wrong-prior join/reader contexts, exact and
one-short native owner limits and preservation of an already charged IR budget.

Native binding/source/observation/support admission always runs through the
actual strict owner reader before correction classification. Only its specific
`InvalidPredecessor` result becomes correction conflict; a foreign corrected
report cannot hide its earlier `BindingMismatch` behind a missing or different
prior join. Successful full native admission is followed by the public bounded
predecessor validator for its original usage receipt. The unavailable full TL
predecessor authority stops potential corrected agreement only after independent
decision predicates are classified; it cannot suppress an already established
refused, failed, unavailable, unsupported, incomplete or conflicting decision.
Genuine foreign corrected native and TL reports exercise both supplied-prior
and missing-prior contexts, retaining refusal priority and no Boolean.

Correction fixtures advance a real progress fact, rather than only changing the
relation and ledger (which the native owner excludes from input identity).
Genuine QObs progress and closure producers/readers admit watermark advancement
from 1 to 2 over the same finite carrier, and the selected native progress and
actual TL request retain those admitted values. Execution remains completed.
Each correction helper first proves relation/ledger-only repetition is rejected,
then asserts the actual prior/current native input identities differ, native
correction issuance succeeds and its original strict reader accepts the complete
prior. Only after that do substitution, foreign-result and precedence assertions
run. No synthetic identity or changed evidence label stands in for new input.
