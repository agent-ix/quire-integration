# TC-109: Original quantity conversion and native dimension normalization

## Description

Exercise public TC-187 U02, U04, U09b and U10 through original checked source
and native owner operations. Generated agreement remains Planned pending shared
runner custody. Source and native observations alone give no generated credit.

## Test Procedure

1. Bind each public vector's complete input and expected cells by reference.
   Parse, form, assemble, check and link original source. Select each original
   checked function body by its actual function identity. Evaluate that body on
   a fresh operation meter without a function-call envelope.
2. Independently admit identical source through the public replay facade. Resolve
   real source quantities through its unit table. Convert through the native
   owner API with fresh identical limits. Compare full outcomes, losses, ordered
   admitted charge records and all ten counters, and check source locations.
3. Require exact 5463/20 K from original 0 degC and 32 degF; require exact 7 m
   from a distinct scale-one alias while preserving distinct original unit IDs.
4. For 100 cm to m use U10's exact tuple. Require 1 m, six ordered charges,
   all counters, and the eight-bit multiply amount. Inject denial specifically
   at the first UnitResultRetain event on fresh real meters; require the exact
   prior prefix, no partial quantity, and an independent healthy sibling.
5. Normalize real admitted L and T dimension maps with owner multiplication,
   division and zero power. Require L and the empty sorted map, with zero
   exponents absent. Select original checked quantity product/division/power
   subnodes through their authored equality operand and typed children. Compare
   evaluation of the original quotient subtree with native multiplication then
   division on the same meter, registering the actual returned compound unit.
   Compare original zero-power evaluation with native power. Do not fabricate
   source dimension declarations or replacement unit identities.

## Expected Results

`tc187_p8_conversion` passes four tests, including eighteen complete source/native
operation observations. U04's two original affine conversions return exact
5463/20 K; U09b returns exact 7 m with distinct original unit keys under the same
native dimension node. Each also agrees at work 0 and 1, stopping at the original
conversion's identity-read and edge respectively, with no partial quantity.

U10 returns exact 1 m under the public tuple. Its full ordered charge records are
identity-read (integer bits 7, occurrence 1), edge (edge 1), rational multiply
(bits 8), rational add (bits 3), target-domain (no size request), and result-retain
(occurrence 1). Every other size request is absent. All ten counters in public
LimitKind order are [8,0,0,0,0,0,1,1,6,1]. Named final denial reports WorkUnits,
limit 5, consumed 5, next charge 1 at UnitResultRetain; the entire admitted prefix
matches the first five healthy records, counters are [8,0,0,0,0,0,1,1,5,0], and
no quantity is returned. A fresh independent sibling completes with the original
healthy ledger. Source and native outcomes and full accounting agree in each case;
source stops retain the original operation location and exact paths have no loss.

U02 normalizes genuine admitted L/T dimension maps to L and the empty map with
no zero exponents. Original closed `(1 m * 1 s) / 1 s` and `1 m ^ 0` subtrees
agree with native owner composition at work 0, 1 and 1024. Successful magnitudes
are exact 1 and compound unit identities retain respectively only the original
metre root at exponent 1 and no terms. Genuine original checked types and native
returned identified units agree. Stops preserve original product or power
locations and full ledgers and counters.

This establishes source/native coverage only. Generated execution remains
Planned pending shared runner custody. Native normalization does not claim
source-derived zero-dimension declaration representation support.
