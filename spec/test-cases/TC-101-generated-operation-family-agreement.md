# TC-101: Execute selected generated function operations against fresh QSL sessions

## Description

Refine IT-019-SC-05 for an initial FR-021 whole-function cohort: the public
`ExactFunctionBody::Scalar` Subtract and Multiply alternatives, and a genuine
`ExactFunctionBody::Call` whose selected callee performs subtraction. Existing
Add evidence does not establish these operations. This procedure supplies no
FR-014 operation-oracle or FR-018 equality-oracle agreement credit.

## Test Procedure

1. Author ordinary pure subtraction, multiplication and relay functions with
   two `Int[0,9]` parameters and an `Integer` result. The relay calls the actual
   subtraction declaration. Separate exercise functions supply genuine selected
   call occurrences. Acquire the source through public QSL checking/emission,
   strictly admit its exact V2 bytes, and derive original declarations, body
   roots, ordered argument references and scalar type handles. Do not substitute
   manually authored IR, source identities or a copied fixture.
2. Lower those actual roots and admit the authenticated contract with its source
   package. Generate through the public exact-function API, using the original
   request positions and the corresponding public body variants. Require each
   selected item to generate; retain its original call/function IDs and returned
   public oracle symbol. Compile the actual artifacts through the existing native
   helper. No proof executor or locally supplied body implementation completes
   the generation path.
3. Independently reacquire the original source and select its actual callable
   under the original owner in a fresh FR-485 registry. Register no generated
   factory in that authority registry. Invoke the generated public symbol and
   the independent session with Integer arguments 4 and 3 and identical fresh
   global allowances at work 0, 1 and 1024. Compare complete typed outcomes and
   call failures, locations, ordered located losses, admitted charges and every
   exposed consumed counter without subtraction, normalization or envelope
   reconstruction.
4. Independently require successful results 1, 12 and 1 for subtraction,
   multiplication and relay respectively. Success has no result location or
   located loss. Work 0 stops at FunctionCall with no admitted charge. Work 1
   admits exactly the outer FunctionCall: direct arithmetic stops at
   IntegerArithmeticOperands; relay stops at the callee's FunctionCall. Both
   stops retain WorkUnits, the original limit and consumed work, next charge 1,
   no value/loss, and the real checked body location. All other consumed scalar
   counters remain zero. These required terminal shapes prevent two matching
   wrong results from establishing agreement.
5. Exercise argument arity and kind on the real public application boundary,
   including an argument list with both a wrong count and wrong kind so the
   native precedence is distinguishable. Include Integer 10 as a genuine value
   outside the authored Int[0,9] parameter domain, to distinguish the source's
   bounded admission from the generator's scalar Integer classification.
   A widened generated input path fails; it is not normalized or credited.
   Compare original native CallFailure
   payloads against the independent session and require zero admitted charges
   and counters. Separately substitute another valid checked source with the
   same authored names but changed arithmetic into the generated owner's source
   authentication. Preserve its typed owner refusal before charge, then invoke
   the original healthy source successfully. Do not invent a key or treat a
   lookup failure as generated execution.
6. Keep the full public FR-021 selection rule explicit. Scalar expands the
   owner's IntegerOperator: Add, Subtract and Multiply have binary execution
   paths; Negate is an owner-defined unsupported unary selection requiring its
   own actual typed generation observation. CompositeEquality expands Equal
   and NotEqual over owner-permitted Boolean, Integer, record, tuple and union
   operands. Call requires a genuine selected callee. Each form additionally
   needs its prescribed result/signature, capability, owner/occurrence,
   duplicate/ambiguous request, refused-item/sibling and operating-boundary
   observations. Reference existing reviewed test symbols only for the exact
   controls they execute. A missing operation or boundary remains Planned under
   IR-842 with its missing integration path; a partial cohort cannot close the
   whole variant or family.

## Expected Results

Status: Planned until these controls execute. Each selected generated function
and independent source session must agree on the complete exposed envelope,
with the independent required values and stops above. Source authentication and
argument refusals remain distinct native boundaries and never become values.

The initial rows are Scalar/Subtract, Scalar/Multiply and Call/subtraction-callee,
with their named argument and owner controls. Existing Add and SC-03 observations
retain their own separate evidence. CompositeEquality operations, Negate's typed
unsupported generation, unexecuted per-form capability/result/occurrence/sibling
and other boundaries remain Planned under IR-842. FR-014 and FR-018 complete
operation inventories and their comparison boundaries remain separate work.
Full IT-019-SC-05 and whole-family agreement remain Planned while any required
row is unexecuted; source-only classification is not agreement.
